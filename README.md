# Telegram Chat через GREEN-API

Тестовое задание на React: интерфейс чата для отправки и получения текстовых сообщений через GREEN-API.
**DEMO**: https://test-in-green-api.vercel.app/
Проект работает с Telegram-инстансом GREEN-API.

## Что реализовано

- ввод учетных данных GREEN-API: `apiUrl`, `idInstance`, `apiTokenInstance`;
- создание нового чата по телефону или `chatId`;
- отправка текстового сообщения через метод `sendMessage`;
- получение входящих уведомлений через `receiveNotification`;
- удаление обработанного уведомления через `deleteNotification`;
- отображение входящих и исходящих сообщений в интерфейсе чата;
- автоматическое создание диалогов при получении новых сообщений;
- загрузка полного списка диалогов через `getChats`;
- обновление статусов исходящих сообщений и загрузка отсутствующего текста через `getMessage`;
- фоновая обработка накопившейся очереди без показа старых сообщений;
- сохранение данных в `localStorage` браузера.

## Проверка с реальным GREEN-API

1. Создайте Telegram-инстанс в GREEN-API.
2. Скопируйте данные инстанса:
   - `apiUrl`;
   - `idInstance`;
   - `apiTokenInstance`.
3. Вставьте эти данные в блок **Инстанс** в приложении.
4. В настройках инстанса включите входящие уведомления (`incomingWebhook: "yes"`). Для получения статусов исходящих сообщений включите `outgoingWebhook: "yes"`. Поле `webhookUrl` оставьте пустым.
5. Нажмите **Получать сообщения** и отправьте новое текстовое сообщение на подключённый Telegram с другого аккаунта. Диалог появится слева автоматически.
6. Выберите диалог, напишите ответ и нажмите **Отправить**. Также можно создать диалог вручную, указав известный `chatId` в блоке **Новый чат**.
7. Кнопка **Проверить уведомление** выполняет один проход по очереди: до 50 событий или до первого пустого ответа. Кнопка **Получать сообщения** запускает непрерывное получение такими проходами.

Самый надежный способ получить корректный `chatId` для Telegram:

1. Включить получение сообщений.
2. Получить входящее сообщение от нужного пользователя.
3. Использовать автоматически созданный чат из списка слева.

## Важное про входящие уведомления

Если отправка работает, но входящие сообщения не появляются, нужно проверить настройки инстанса GREEN-API:

- инстанс должен быть именно Telegram;
- входящие уведомления должны быть включены;
- для HTTP polling через `receiveNotification` поле `webhookUrl` должно быть пустым;
- если очередь уведомлений пустая, приложение покажет соответствующий статус.

Для диагностики можно нажать **Проверить уведомление**. JSON последнего нового уведомления доступен в раскрывающемся блоке **Последнее уведомление GREEN-API**. Старые события этот блок не обновляют.

### Новые сообщения и накопившаяся очередь

Все диалоги загружаются через `getChats`, сохранённая переписка остаётся доступной после обновления страницы.

Накопившиеся до открытия страницы уведомления обрабатываются в фоне: дополняют список диалогов, но не заполняют переписку старыми событиями, не переключают выбранный чат и не вызывают прокрутку. Новые сообщения отображаются по мере получения.

Очередь GREEN-API последовательная, поэтому большой объём старых событий может задержать получение новых.

### Статусы и GetMessage

`outgoingMessageStatus` содержит `chatId`, `idMessage` и статус (`read`, `delivered` и другие), но не содержит текста. Если сообщение уже есть локально, приложение обновляет его статус. Если текста нет, автоматически запрашивает его через `getMessage` по паре `chatId` и `idMessage`.

Запросы текста выполняются последовательно, с паузой 1,1 секунды перед каждым запросом, отдельно от получения уведомлений. До загрузки текста запись скрыта. Для старых событий очереди `getMessage` не вызывается. Ошибка загрузки выводится в строке состояния.

`deleteNotification` подтверждает обработку события и удаляет его из очереди уведомлений. Переписку в Telegram этот метод не удаляет.

Описание методов: [получение уведомлений](https://green-api.com/telegram/docs/api/receiving/technology-http-api/), [GetMessage](https://green-api.com/telegram/docs/api/journals/GetMessage/).

### Локальные данные

Приложение сохраняет учётные данные, включая API-токен, диалоги и сообщения в `localStorage` текущего браузера. Используйте его на доверенном устройстве. Автоматическое получение после перезагрузки нужно включить снова.

Кнопка **Очистить** очищает локальные диалоги и сообщения, но сохраняет данные подключения и отдельный фоновый архив. Она не удаляет переписку в Telegram и не очищает очередь GREEN-API.

## Деплой на Vercel

Проект подготовлен для деплоя на Vercel. Для production-режима добавлены serverless API routes:

```text
api/green/send.js
api/green/receive.js
api/green/delete.js
api/green/message.js
api/green/chats.js
```

Они повторяют локальный proxy из `vite.config.js`, поэтому frontend обращается к тем же адресам:

```text
/api/green/send
/api/green/receive
/api/green/delete
/api/green/message
/api/green/chats
```

## Сборка

```bash
npm run build
```

Для Windows:

```powershell
npm.cmd run build
```

Собранные файлы появятся в папке `dist`.

`npm run preview` позволяет посмотреть собранный интерфейс, но API-прокси подключён только к серверу разработки. Для работы с GREEN-API локально используйте `npm run dev`, для опубликованного приложения — Vercel Functions.

## Основные файлы

- `src/App.jsx` — основной интерфейс чата и логика обработки сообщений;
- `src/greenApi.js` — клиентские методы для обращения к `/api/green/*`;
- `src/notifications.js` — разбор уведомлений, обработка статусов, объединение ответа GetMessage и определение старых событий;
- `vite.config.js` — proxy-запросы к GREEN-API для локального запуска;
- `api/green/*.js` — serverless API routes для Vercel;
- `src/styles.css` — стили интерфейса.
